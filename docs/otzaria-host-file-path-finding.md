# ממצא למתחזק אוצריא: נתיב הקובץ בדיווח תיקון מתוסף

התוסף אינו עוקף את הבעיה הזאת ואינו שולח דיווחים בעצמו. התיקון שייך למארח.

## הממצא

ב־`feedback.submitBookCorrection` המארח בונה `PluginBookReportMetadata.filePath` מתוך `libraryDisplayPath`:

- `lib/plugins/bridge/plugin_bridge_adapter.dart:6227-6235`: `filePath: libraryDisplayPath(information.fileDetails['נתיב הקובץ'] ?? '') ?? ''`.
- `lib/book_common/view/book_source_dialog.dart:335-344`: `libraryDisplayPath` היא פונקציית תצוגה. היא מסירה את הקידומת `אוצריא/` ואת סיומת הקובץ, ומחזירה null לנתיב שאינו בספרייה. במקרה כזה נשלחת מחרוזת ריקה.
- `lib/plugins/services/plugin_book_correction_service.dart:217`: הערך עובר כמו שהוא לדיווח שנשלח לאתר.

מאתר המקור באתר (`resolver.js`) מצפה לנתיב מלא שמתחיל ב־`אוצריא/` ומסתיים ב־`.txt`. נתיב קטגוריות מקוצר כמו `שו״ת/אחרונים/בית הלוי/בית הלוי חלק ג` נכשל ב־`not_found/no_candidate_path`. זה קורה לפני כל גישה למאגר המקור.

ההפניות למארח נבדקו בעותק המקומי של אוצריא, בענף `feat/local-correction-recovery-2152` ב־`245aaca1f`. דרישת האתר וכשל ה־resolver לקוחים מהחקירה המבודדת שמתועדת ב־`docs/QA.md` (19 באוקטובר 2026). בשלב הזה לא נקרא קוד האתר מחדש.

## השפעה

השליחה עצמה מצליחה (HTTP 200). איתור המקור האוטומטי נכשל, והדיווח עובר לטיפול ידני. הדבר אינו נראה לתוסף, כי תוצאת `feedback.submitBookCorrection` אינה כוללת את מצב הניתוב או האיתור באתר.

## כיוון אפשרי (להחלטת המתחזק)

כדאי להעביר ב־`filePath` את הנתיב היחסי המלא בספרייה, כולל `אוצריא/` והסיומת, במקום ערך התצוגה. בנוסף, אפשר לשקול להוסיף לחוזה התוצאה שדה שמבחין בין כניסה לתור התיקונים באתר לבין ניתוב לדוא״ל בלבד. אם יתווסף שדה כזה, התוסף יוכל להציג סטטוס מדויק יותר.
