# תיקוני ספרים לאוצריא

תוסף ניסיוני, גרסה 0.3.1, לאוצריא 0.9.98.2 ומעלה. הנוסח נערך בקורא של אוצריא עצמה, עם הבאנר וסימון הפסקאות המתוקנות שלה. התוסף שומר את התיקונים, מציג התנגשויות להחלטה ושולח דיווחים דרך `feedback.submitBookCorrection`. הספר, קובץ המקור ומסד הספרייה אינם משתנים.

אוצריא 0.9.98.2 היא הגרסה הרשמית הראשונה שכוללת את כל ה־API שהתוסף צריך: סשני התיקון והטיוטות, `feedback.submitBookCorrection` וכפתור ההחלפה בשדה החיפוש (כולם מ־0.9.98.1 במפרט אוצריא). התוסף אינו דורש רשת: הוא אינו מצהיר על `network` או על הרשאת `network.*`, הדיווחים נשלחים דרך אוצריא, והוא זמין גם במצב „ללא גישה לאינטרנט”. הקוד הקודם של [גרסה 0.2.2](https://github.com/Yehuda-Zakesh/otzaria-book-corrections/tree/7c55bbd9c832e4aca4ee9eec43975bf25e82b576) נשאר זמין בהיסטוריית המאגר.

## שימוש

- דף התוסף מחולק למסכי **תיקונים**, **היסטוריה** ו־**הגדרות**, עם ניווט בסרגל ומקלדת RTL. כל מסך שומר את מיקום הגלילה שלו במעבר למסך אחר.
- סמל הדיווח בסרגל העליון פותח **דיווח למפתח התוסף**. הטופס משתמש ב־`feedback.report` של אוצריא, שמציגה אישור ומעבירה את הפנייה למפתח. ביטול או כשל משאירים את הטקסט לעריכה; `queued` מוצג כהמתנה לשליחה. זו פנייה על התוסף, בנפרד מתיקון נוסח ספר.
- בספר טקסט: לחיצה ימנית (גם בלי סימון) ← **תיקון הספר בקורא**. הלחיצה נושאת את מזהה הלשונית המדויק, גם כשהספר פתוח בכמה לשוניות. אפשר גם לבחור לשונית ברשימה שבדף התוסף.
- כפתור הסרגל **תיקון הספר בקורא** אינו נושא מזהה לשונית (פער במארח). הוא פועל רק כשיש לשונית אחת של אותו ספר; אחרת מוצגת בקשה לבחור.
- העריכה, השמירה העמידה ו**סיום עריכה** נעשים בקורא של אוצריא. בדף התוסף: **שמירה ושליחה**, **סיום עריכה**, תיקונים ממתינים, התנגשויות והיסטוריה.
- בכרטיס הספר שבעריכה, **חיפוש והחלפה** מחליף מילה או ביטוי בכל פסקאות הספר אחרי תצוגה מקדימה ואישור. המקור נטען פעם אחת לסשן ונשמר בזיכרון לחיפושים חוזרים; אוצריא מאמתת מחדש את כל הפסקאות המשתנות לפני החלה. אין צורך לגלול קודם לאורך הספר או לטעון את כל פסקאותיו בקורא.
- חיפוש והחלפה זמינים בדף התוסף ובכפתור שבתוך שדה החיפוש של הקורא.
- **איחוד לדיווח אחד** זמין גם כשהספר סגור: הצעות לאותה פסקה שמשנות מקומות שונים מאוחדות ונשמרות בתוסף, ללא פתיחת קורא וללא שליחה אוטומטית. אם השינויים מתנגשים יש לבחור נוסח בעריכה בקורא.
- בדף הדיווח למפתח, **תיקיית הלוגים** מציגה את קובצי `logs/` הפרטיים לצפייה ולהעתקה. נשמרים זמני RPC, ניסיונות חוזרים, קודי שגיאה, מיקומי קוד ואירועי סשן, ללא תוכן ספרים, נוסחי תיקונים או מיילים. נשמרות עד שש הפעלות, 250 אירועים לכל הפעלה. הלוגים אינם מצורפים לדיווח אוטומטית, ויש להעתיק אותם מתיקיית הלוגים ולהדביק בדיווח ידנית. מגבלת אוצריא היא 5,000 תווים ללא קובץ מצורף, ולכן תיאור המשתמש מוגבל ל-3,000. פתיחת התיקייה בסייר המערכת דורשת הרחבה בצד אוצריא.
- בסרגל הקורא ובתפריט לחיצה ימנית: **שליחת תיקוני הספר** שולחת את ההצעות השמורות של אותו ספר אחרי אישור, גם בלי לפתוח את דף התוסף. יש לאשר את הרשאות ההפעלה ברקע בניהול התוספים. שמירה שלא הושלמה חוסמת שליחה של נוסח ישן.
- שליחה מבקשת תיקון מובנה (`requireTextCorrection: true`). כשאוצריא אינה יכולה להכין אותו, למשל בשינוי שחוצה תגיות, המשתמש מחליט אם לשלוח את המקור וההצעה כדיווח חופשי לבדיקה ידנית. אופן הטיפול תלוי במקור הספר ובשרת; ביטול משאיר את ההצעה שמורה.
- בדף התוסף מוצגים עיצוב המקור וסימון השינויים יחד: מודגש, נטוי, קו תחתון, כותרות, גדלים, כתב עילי/תחתי ומאפייני CSS נתמכים. העיצוב משוחזר רק כשמקור ה־HTML תואם לטקסט הקנוני. תסריטים, תמונות, קישורים פעילים ו־CSS שרירותי אינם נטענים. עיצוב מבוסס מחלקות וטבלאות אינו משוחזר במלואו.
- עיצוב שדה התיקון תלוי בבניית אוצריא: בחוזה התיקונים הטקסט נשמר כטקסט פשוט, ובקוד המארח המעודכן כבר קיים controller המשמר חלק מעיצוב המקור. בחירה ומחיקה חוצת פסקאות מקור והדגשות חיפוש בתוך השדה הנערך עדיין דורשות שינוי במארח; התוסף אינו יכול לשנות את שדה Flutter דרך ה־API הקיים. **סיום עריכה** מחזיר לקריאה רגילה ושומר את ההצעות לשליחה. [פרומפט להמשך בצד אוצריא](docs/otzaria-followup-prompt.md).
- הדיווח מזוהה באמצעות כתובת המייל המוגדרת בדיווח השגיאות באוצריא. בקוד האתר קיים משלוח הודעת תודה לאחר אישור; הגעה בפועל תלויה בגרסת האתר, בהעדפות הדיוור ובשירות המייל. אישור השליחה בתוסף אינו אישור התיקון.
- סטטוס `queued` מוצג כ„בתור הדיווחים של אוצריא — טרם נשלח לאתר”. `sent` עם `correctionSupported: true` מוצג כ„השליחה דרך אוצריא הושלמה — סטטוס הטיפול באתר אינו ידוע”: האתר מחזיר אישור זה גם לדיווחים שהוא מנתב לדוא״ל בלבד, ולכן אין בו הוכחה לכניסה לתור התיקונים, לאישור או לפרסום.
- טיוטות 0.2.2 מוצגות לקריאה בלבד. תיקון שנשאר בתוך פסקה אחת ושהמקור שלו לא השתנה אפשר להעביר לקורא; כל השאר נשאר להחלטת המשתמש.

חוזה השמירה, האישור והמיגרציה: [docs/correction-sessions.md](docs/correction-sessions.md).

## פיתוח ובדיקות

נדרש Node.js 22 ומעלה; אין תלויות npm. `npm run dev` בונה את `plugin/app.bundle.js` בכל שינוי. טוענים את `plugin/` כתוסף פיתוח באוצריא 0.9.98.2 ומעלה.

סמלי הממשק הם [Fluent UI System Icons של Microsoft](https://github.com/microsoft/fluentui-system-icons), בהתאם למשפחת הסמלים באוצריא. רישיון MIT כלול בחבילת התוסף (`FLUENT-ICONS-LICENSE.txt`).

`npm run qa` מריץ check (תחביר, bundle, דרישת מינימום 0.9.98.2 וחוזה ה־API), בדיקות Node, בדיקת דפדפן ואריזה ל־`dist/book-corrections-0.3.1.otzplugin`. בדיקות Node והדפדפן משתמשות במודל של חוזה המארח (`test/fake-otzaria.mjs`); זו **אינה** בדיקת אינטגרציה מול אוצריא. האימות הרשמי ב־CI מוצמד למפרט של תג השחרור `0.9.98.2+807` (`1b9f23664`). הבדיקות החיות והמגבלות מתועדות ב־[docs/QA.md](docs/QA.md).

הריפו: [Yehuda-Zakesh/otzaria-book-corrections](https://github.com/Yehuda-Zakesh/otzaria-book-corrections).

## CI ופרסום ב-GitHub

- **Package plugin**: ריצה נפרדת לאריזה בלבד, בכל push ל-main, PR אליו או ידנית. בודקת ואורזת את התוסף להורדה כ-artifact בשם `book-corrections` למשך 14 יום. אינה יוצרת Release, אינה משתמשת בסודות ואינה פונה לחנות אוצריא.
- **CI**: בכל push ל-main, PR אליו או הפעלה ידנית. בדיקות ב-Windows וב-Linux עם Node 22 ו-24, QA בדפדפן, אימות רשמי מול מפרט ה־API של 0.9.98.2 ואריזה; דרישת ההתקנה במניפסט היא 0.9.98.2. קובץ ההתקנה ותצלומי הבדיקה נשמרים כ-artifacts למשך 14 יום.
- **Publish GitHub release**: ידנית דרך Actions או בדחיפת תג `v<version>` התואם לגרסת המניפסט. רצה קודם כל חבילת ה-CI, ורק לאחר הצלחה מתפרסם אותו artifact כ-Release. תג שאינו תואם לגרסה נדחה; Release קיים אינו נדרס.
- **Publish to Otzaria**: ידנית דרך Actions, מענף main בלבד. מריצה CI ומשתמשת באותו קובץ שנבדק. יש להגדיר `OTZARIA_USER` ו-`OTZARIA_PASSWORD` ב-[Repository secrets](https://github.com/Yehuda-Zakesh/otzaria-book-corrections/settings/secrets/actions). בפרסום ראשון מצורף `screenshots/main.png`, ויש לסמן הסכמה לקבלת דיווחי משתמשים. פרסום ראשון ממתין לאישור מנהל החנות.

פרסום אינו מופעל אוטומטית בדחיפה ל-main. ריצות PR ו-CI אינן מקבלות סודות חנות ואינן מפרסמות. ה-Actions מוצמדים ל-commit מאומת. [מקור כלי האימות והפרסום הרשמי](https://github.com/Otzaria/otzaria-plugin-validator).

בדיקות הרשת האוטומטיות משתמשות בהדמיה. בבדיקה ידנית בוצע ניסיון לשלוח הצעות לאוצריא; בהיסטוריית התוסף הוצג אישור לתיקון מובנה. למגיש אין גישה לאתר התיקונים, ולכן הופעת ההצעות באתר וקליטתן בפועל לא אומתו עצמאית. אין לבצע שליחות בדיקה נוספות ללא בקשה מפורשת.
