# תיקוני ספרים לאוצריא

תוסף ניסיוני, גרסה 0.4.0, לאוצריא 0.9.98 ומעלה, הדורש חיבור לרשת. פותחים ספרים בלשוניות, מתקנים ולוחצים **שלח דיווח**. השינויים נשלחים לממשק הדיווח הישן כהצעות תיקון לבדיקה ידנית. השליחה אינה משנה את ספרי הספרייה המקומיים.

## מצב נוכחי

- מסך ספר מלא עם ניווט בצד ימין, עץ כותרות עם הרחבה וצמצום, חיפוש בכותרות וחיפוש בתוך הטקסט הערוך. הצבעים והגופנים מתקבלים מאוצריא; מידות וצורת השורות מותאמות לרכיבי הניווט שלה. רכיבי הניווט של התוסף כתובים ב-HTML/CSS ולא דורשים API ניווט חדש.
- ספר מועבר ממסך העיון באותו מיקום, לפי הפסקה והיסט הבחירה שה-SDK מספק. המיקומים ממופים מחדש לאחר עריכה, הוספה או מחיקה.
- כפתור טעינת הספר ממורכז. כשכמה ספרי טקסט פתוחים, בוחרים איזה מהם לייבא. PDF אינו עורך טקסט.
- כפתור **פתח ספר נוסף** פותח ספר בלשונית חדשה. מעבר בין הלשוניות משמר לכל ספר את הטקסט, תור השליחה, הגלילה, הבחירה, החיפוש ותוכן העניינים. ספר שכבר פתוח נבחר מחדש בלי לדרוס את הטיוטה. בסגירת לשונית עם תיקונים שלא נשלחו מוצג אישור מחיקה.
- כל הלשוניות נשמרות ומשוחזרות בטעינה מחדש. טיוטה מגרסה קודמת נטענת כלשונית ראשונה. חצי שמאל/ימין עוברים בין לשוניות ב-RTL; Home/End עוברים לראשונה/אחרונה.
- האייקון באוצריא הוא `document_edit_24_regular`, ללשונית התוסף ולפעולות פתיחת ספר לתיקון.
- כתובת המייל אינה מוצגת בתוסף. לפני שליחה נקראת הכתובת מהגדרות אוצריא; אם היא חסרה מופיעה ההודעה **יש לעדכן מייל לפני השליחה בהגדרות התוכנה**.
- טיוטת העריכה נשמרת. השליחה סדרתית, עם מזהים יציבים ושמירת התקדמות, כך שניסיון חוזר אינו שולח מחדש דיווחים שסומנו כנשלחו.
- אין שימוש בתור הדיווחים המובנה. כשל בשליחה שומר את הטיוטה והתקדמות השליחה לניסיון ידני בהמשך, ללא שליחה אוטומטית ברקע.
- לספר יש פס גלילה רציף אחד, שעוצר בתחילת הספר ובסופו. מאחורי הקלעים נפרסת רק סביבת הקריאה (עד שלושה מקטעים של 16,001 תווים), כדי לשמור על ביצועים בספרים גדולים. אין סרגל אחוזים או כפתורי מעבר בין מקטעים. הניווט בצד עוקב אחר המיקום הגלוי, פותח את מסלול הכותרת ומביא את השורה הפעילה לתצוגה. החיפוש והטיוטה כוללים את הספר המלא; בחירה והעתקה בשדה העריכה כוללות את חלון הטקסט המוצג.
- אחרי שליחה מוצלחת אפשר להמשיך לתקן באותו ספר. תיקונים זהים שכבר דווחו אינם נשלחים שוב.

## שליחה ישירה ותאימות

השליחה משתמשת ב-`network.fetchStream` עם הרשאת `network.access`, בבקשת POST אל `https://otzaria.org/api/reportingerrors`. כל דיווח מכיל את המקור, הנוסח המוצע, שם הספר ומיקום הקטע. הצלחה מסומנת רק לאחר HTTP 200 ותשובת JSON עם `success: true`. אין תלות ב-API החדש או שימוש בהרשאת `feedback.send_email`.

פותחים את הספר לתיקון מהכפתור בסרגל הספר, או בלחיצה ימנית על טקסט מסומן.

## תאימות ושליחה

נדרשת אוצריא 0.9.98 ומעלה. השליחה מבוססת על ה-SDK הקיים, ללא קריאות ל-`feedback.submitBookCorrection`. [פרטי השליחה ודרישת הרשת](docs/legacy-reporting.md).

הטיוטות ותורי הדיווחים נשמרים מקומית, בנפרד לכל ספר. דיווחים שנשלחו אינם נשלחים שוב; כשל נשמר לניסיון ידני. אין תור של אוצריא או שליחה אוטומטית כשהחיבור חוזר. עבודת ה-API העתידי שמורה בענף [api/native-book-corrections](https://github.com/Yehuda-Zakesh/otzaria-book-corrections/tree/api/native-book-corrections), כולל המימוש האחרון ו-patch מעודכן לאוצריא.

## התקנה ופיתוח חי

נדרש Node.js 22 ומעלה; אין תלויות npm.

`npm run dev` עוקב אחר קובצי המקור ובונה אוטומטית את `plugin/app.bundle.js`. באוצריא טוענים את תיקיית `plugin` כתוסף פיתוח. שינויי HTML/CSS נקלטים ישירות; אין לערוך את ה-bundle שנוצר. שינוי בקוד Dart של אוצריא דורש גם Flutter reload/restart ואינו חלק מטעינת התוסף החיה.

`npm run pack` בונה `dist/book-corrections-0.4.0.otzplugin`. `npm run qa` בודק תחביר, עקביות גרסאות ו-bundle, מריץ את בדיקות הקוד והדפדפן ואורז. `npm run test:browser` מפעיל Chrome או Edge במצב headless ובפורט זמני, עם SDK ושליחה מדומים; אפשר להגדיר `CHROME_PATH`. הריצה כוללת לשוניות, שחזור טיוטות, מקלדת, בחירה, חיפוש, גלילה בספר גדול וגבולות הספר. `npm run test:browser:attached` משתמש בדפדפן פתוח בפורט 9227 או `CDP_PORT`.

הטעינה תומכת בספרים עד 10MB. בקשות מיפוי ואחסון נשלחות במרווח 20ms עם ניסיון חוזר מוגבל לחסימת קצב. תגיות HTML מוסרות לפי כללי אוצריא, ולכן העורך משנה טקסט ולא עיצוב ספרים.

הריפו: [Yehuda-Zakesh/otzaria-book-corrections](https://github.com/Yehuda-Zakesh/otzaria-book-corrections). העותק `upstream-otzaria`, חבילות פלט, לוגים, פרופילי דפדפן ותצלומי מסך אינם נכללים בריפו.

## CI ופרסום ב-GitHub

- **CI**: בכל push ל-main, PR אליו או הפעלה ידנית. בדיקות ב-Windows וב-Linux עם Node 22 ו-24, QA בדפדפן, אימות רשמי של אוצריא מול גרסה 0.9.98 ואריזה. קובץ ההתקנה ותצלומי הבדיקה נשמרים כ-artifacts למשך 14 יום.
- **Publish GitHub release**: ידנית דרך Actions או בדחיפת תג `v0.4.0` התואם לגרסת המניפסט. רצה קודם כל חבילת ה-CI, ורק לאחר הצלחה מתפרסם אותו artifact כ-Release. תג שאינו תואם לגרסה נדחה; Release קיים אינו נדרס.
- **Publish to Otzaria**: ידנית דרך Actions, מענף main בלבד. מריצה CI ומשתמשת באותו קובץ שנבדק. יש להגדיר `OTZARIA_USER` ו-`OTZARIA_PASSWORD` ב-[Repository secrets](https://github.com/Yehuda-Zakesh/otzaria-book-corrections/settings/secrets/actions). בפרסום ראשון מצורף `screenshots/main.png`, ויש לסמן הסכמה לקבלת דיווחי משתמשים. פרסום ראשון ממתין לאישור מנהל החנות.

פרסום אינו מופעל אוטומטית בדחיפה ל-main. ריצות PR ו-CI אינן מקבלות סודות חנות ואינן מפרסמות. ה-Actions מוצמדים ל-commit מאומת. [מקור כלי האימות והפרסום הרשמי](https://github.com/Otzaria/otzaria-plugin-validator).

לא נשלחו דיווחי בדיקה אמיתיים. בדיקות רשת משתמשות בהדמיה; יש לבדוק שליחה אמיתית רק עם תיקון שרוצים לדווח עליו.
